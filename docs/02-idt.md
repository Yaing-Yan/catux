# 第 2 课（2a）：中断与异常 —— CPU 的"门铃系统"

## 为什么需要中断

阶段 1 里我们读串口状态用的是"忙等"（while 循环反复问：好了吗？好了吗？）。
如果键盘也这么搞，CPU 就什么正事都不能干，只能一直盯着键盘端口。
中断就是解决方案：**平时该干嘛干嘛，事件发生时硬件主动"按门铃"，
CPU 暂停手头工作去处理，处理完回来继续**。

## 异常 vs 中断

| | 来源 | 例子 |
|---|---|---|
| 异常（0~31） | CPU 自己 | 除零、非法指令、页故障 |
| 硬件中断（32 起） | 外部设备 | 时钟、键盘、磁盘完成 |

它们走同一套机制：IDT。

## 完整链路（以除零为例）

```
CPU 执行 div 指令，除数为 0
  → 硬件自动往栈上压 3 个值（eip、cs、eflags）
  → 查 IDT 第 0 号门 → 跳到 isr0（isr.S 里的汇编桩）
  → 桩补一个假错误码 0（统一栈布局），压异常编号 0
  → call isr_dispatch(num=0, err=0)   ← 你的 C 代码
  → 打印警报，return → 桩里 cli+hlt 挂机（2a 还不会恢复现场）
```

## 关键设计：IDT（中断描述符表）

- 固定 256 项 × 8 字节，每项一个"门"：处理函数地址 + 代码段 + 属性
- 向量 0~31 被 CPU 钦定为异常；32~255 留给 OS（2b：时钟=32，键盘=33）
- 用 `lidt` 装表：它要的是一个 6 字节结构（表大小-1 + 表地址）
- flags = 0x8E：存在(1) | ring0(00) | 32位中断门(0xE)

## 为什么有的异常有"错误码"

部分异常（页故障、General Protection 等）CPU 会多压一个 32 位错误码，
说明出错的具体原因（比如页故障：是缺页还是权限不够？读写？用户态还是内核态？）。
有的异常压、有的不压——汇编桩用两个宏统一补 0，让 C 侧无感知。

## 一个值得记住的事实

内核最著名的恐慌之一"Kernel Panic - not syncing: ..."，
最初形态就是本课这样的一个异常分发器在打印。
阶段 2b 我们把时钟和键盘接上，内核就真正"活"了。
